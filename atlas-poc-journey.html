Two lineages, kept separate

This matters more than any single number. Atlas has a governed target lineage and a proven reference lineage. They are at different stages and are not the same chain.

Governed target lineage

  1. Road LTL 1.5 frozen candidate
  2. Operational Knowledge v2 certified
  3. Recursive work decomposition certified
  4. Canonical WorkDefinition compiler proven, not persisted
  5. Client Binding incomplete
  6. Runtime projection incomplete

Proven reference lineage

  1. Road LTL V1.2 reference
  2. Domain Warehouse v2.3 lossless projection
  3. Malkom 3.0 adapter working end to end

This is the chain that produces the machine-readable output in step 5.

Stated plainly: the Malkom output shown here was generated from the V1.2 reference lineage. It was not generated from Road LTL 1.5, the certified decomposition, or the canonical WorkDefinition compiler. Connecting the governed lineage to a runtime adapter is real remaining work, not something this proof of concept demonstrates.

Why there is no completion percentage

A single score would average together things that are not comparable — a certified decomposition, an unpersisted compiler, and bindings that depend on a client supplying values Atlas cannot generate. Each layer's real state is shown above instead. Known open items are tracked as explicit gaps, not folded into a number.
