- U1. A source changes: which Universe constructs must be re-checked (impact scope)?

## 5. Granularity decision and justification
DECISION: Source Watch granularity = domain / family (construct) level. Entity-level source tagging is NOT adopted.
Why domain/family level supports impact analysis (U1-U5):
1. Reach: 54 of 67 sources already resolve to at least one domain from fields in the frozen file; 45 of them reach 7 or fewer domains, 23 reach 1-3. Every source sits in a reference-placement group. After IC-4 the remaining 13 get an explicit route, so all 67 sources have a construct route.
2. The unit of Source Watch work is the changed text of one source (U2). Delta research starts from the issuer's change note or diff and identifies the affected claims; it does not need a pre-tagged entity to begin. The domain scope bounds which constructs the claim can touch, and the derived entity list bounds the reviewer's check list.
3. Entity tags would not be source-grounded. W1-09 (provisional, DONE_CLAIMED, unverified) sampled 60 entities: 13 PASS (standards-defined), 21 NOTE, 24 LIMITATION (process-framework-only, specialization, or software category with function-level support only), 2 NO_BASIS. Systems are generic categories and, per Owner input of 2026-10-11 08:11, stay generic categories mapped by function. Tagging 265 entities with source ids would therefore be an assessor assertion for most of them and would create false precision in lineage (U4).
4. Volume and upkeep: 265 entity-to-source assignments exceed the PATCH ceiling of 25 mappings in the frozen protocol, so entity tagging cannot be a PATCH; it would be an Owner-escalated import-layer build that goes stale whenever aliases or entities change (W1-22).
5. Where entity level might have helped, it does not: the 9 broad sources (SCOR, APQC, GS1 family, UN/CEFACT RDM, ISO 9001/44001) are framework-wide, and a changed node still has to be located by delta research.
Known limits of this decision (disclosed): the derived entity scope is wide (median 79, p90 146 of 265) so reviewers see a large check list for broad sources; 13 sources have no domain route; 26 entities have no source route. These are handled as import conditions, not ignored.
REVISIT TRIGGER (for the Owner, not a task): if the W1-29 dry run shows a single-claim source change whose derived scope cannot be dispositioned by a reviewer, or W1-12 shows that domain/family level misses a legal-source impact (U5), the Owner may require entity-level tags for a bounded set (for example the 46 unreachable ids plus high-risk sources) as a PATCH-class import item.
