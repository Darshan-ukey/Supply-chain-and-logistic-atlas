# Universal Daughter Renderer Contract V1

## Fixed application shell

### Header
- Module badge/code
- Module name + semantic version
- publication/depth badge
- breadcrumb: Universe → family → module
- global switcher: Canvas | Universe | Daughter
- daughter selector

Header must not overlap at 1440px, 1280px, tablet or mobile.

### Primary daughter navigation
1. Overview
2. Compose Context
3. Execution Graph
4. Reference Configurations
5. Enterprise Lenses
6. Sources

`Systems / Objects / Documents / Controls / Actors / Data / Exceptions / Sources` are graph/Inspector projections, not separate bespoke pages unless a future platform-wide decision changes the renderer.

## Overview
- Bold domain/service statement
- concise practical description
- metadata chips: A3, A4/A5, projections, lenses, overlay families, reference configs, depth/status
- architecture/boundary panel, concise only
- no source/methodology wall above the fold

## Compose Context
- Primary controls visible: operating role, movement/topology, node.
- Advanced controls collapsed by default: jurisdiction, regime, conditions, contract/service context.
- Current compatibility state always visible.
- Invalid/locked options remain visible with “why unavailable”.
- Active overlays and graph-impact summary visible.

## Execution Graph
- One governed graph with projections, not duplicated scenarios.
- Default End-to-End view.
- Projections grouped for density:
  - Flow: End-to-End, Information, Data, Documents
  - Responsibility: Actors, Controls, Exceptions
  - Technology: Systems
  - Enterprise: Enterprise dependencies
  - Evidence: Sources
- search by process, object, actor, system, document.
- selected task opens Inspector.
- actions: Open in Canvas, Trace upstream, Trace downstream, Reset.

## Inspector
Use progressive sub-tabs:
1. Summary — hierarchy, state, outcome, confidence.
2. Execution — trigger, states, event, decision, rule, control, clock, action, evidence.
3. Responsibility — performer, owner, decision authority, custody, financial and exception ownership.
4. Systems & Data — inputs/outputs, objects, documents, events, producer/authority/consumer exchanges.
5. Relationships — incoming/outgoing graph, upstream/downstream, variants/recovery.
6. Evidence — provenance claims, claim boundary and sources.

## Reference Configurations
- 3–10 curated examples where meaningful.
- Always generated by the same composer/rule engine.
- Never stored as duplicated process graphs.

## Enterprise lenses
- Common Universe lens registry.
- Daughter marks directly-related/dependency/other, never invents a private lens taxonomy.

## UX rules
- Maximum useful information per view; detailed evidence behind disclosure.
- Long canonical task labels can have 2–4 word `semanticZoomLabel`; full name remains canonical in Inspector.
- No static A3→A5 card dump for an A5-verified module.
- Mobile uses same information architecture, not a reduced-content page.
