# V6.2.3 / v0.6.5 Strict Guardrails

1. **Frozen foundation cannot change.** Page 0 V6.2.2 and integrated V6.2.2 + Road LTL V1.2 are retained byte-for-byte under `frozen/` and as `public/atlas-v6.2.2-frozen.html`.
2. **V6.2.3 is additive only.** The only permitted difference in deployed `public/atlas.html` is the block between `V6.2.3 ADDITIVE GUIDE START/END` markers. Removing that block must reproduce the frozen integrated V6.2.2 hash exactly.
3. **No existing taxonomy/source/rule/applicability/process record is edited by the guide layer.**
4. **One knowledge source for UI + chatbot.** The guide and resolver derive from `data/atlas-constitution-v6.2.3.json`.
5. **Provenance first.** Source-native, crosswalk, Atlas analytical construct, Atlas child synthesis and runtime/presentation state remain distinct.
6. **Source boundary first.** A source cannot substantiate claims outside its stated support/claim boundary.
7. **Ambiguity cannot be guessed.** If exact ID/current clicked context does not resolve a repeated term, the chatbot asks a clarification question before invoking the LLM.
8. **Gemini is the explanation layer, not the truth classifier.** It receives governed evidence packets and may provide clearly-labelled illustrative examples, but cannot determine Atlas provenance/applicability/client truth from pretrained knowledge.
9. **Plain English does not replace governance detail.** Default order is practical explanation first, then classification/provenance/source/applicability.
10. **Runtime UI state is not source taxonomy.** Labels such as `OTHER_LTL_KNOWLEDGE` must be identified as runtime trace relevance when that is their actual namespace.
11. **Client truth remains separate.** CONFIRMED / OBSERVED / PUBLICLY_EVIDENCED / INFERRED / REFERENCE_ONLY / UNKNOWN may not be silently promoted.
12. **Atlas corrections are advisory only.** Intelligence can identify a potential correction; the administrator manually creates a future governed Atlas source version.
13. **No browser secrets.** LLM, research and Supabase secret keys remain server-side environment variables.
14. **No production confidential client data before tenant isolation/RLS.**
