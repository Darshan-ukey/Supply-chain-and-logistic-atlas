# Atlas Intelligence v0.6.6 — Strict Guardrails

## Frozen Atlas
- No Page 0 V6.2.2 writes.
- No Road LTL V1.2 writes.
- No V6.2.3 guide edits.
- No Constitution edits.
- No taxonomy/source/relationship/applicability writes.
- Presentation uses runtime DOM classes only; source bytes remain unchanged.

## Simulation
- Standard journey derives from STANDARD processes connected by governed `PRECEDES` edges.
- The STANDARD path must have one root, no cycle, no ambiguous next step and must cover every STANDARD process.
- `BRANCHES_TO`, `ENABLES`, `TRIGGERS`, `MAY_TRIGGER`, `BLOCKS`, `ESCALATES_TO`, `RECOVERS_TO`, `ITERATES_TO_NEXT_LEG` and other relationship types remain semantically distinct.
- Multiple recovery/branch choices are shown; the engine/LLM does not silently choose one.
- LLM never determines path, applicability, blocking or regulatory scope.

## Handoff and data
- Shared canonical objects are intersections of explicit upstream outputs and downstream inputs.
- Shared identifiers are intersections of explicit process identifier statements.
- No API, EDI or database payload fields are inferred.
- Missing field-level detail is explicitly `NOT_MODELED`.

## Risk
- Every risk signal includes provenance/basis.
- No invented probability, severity, SLA effect, monetary impact or expected loss.
- Client risk statements are `CLIENT-EVIDENCED` only for evidence-backed client statuses.

## Client twin
- `UNKNOWN` remains unknown.
- `REFERENCE_ONLY` remains reference-only.
- Difference from reference does not equal gap.
- Client names/systems never replace canonical Atlas entities.
- TO-BE remains advisory until human-approved.

## Chat/LLM
- Query Trust Gate and Evidence Intake Trust Gate are separate.
- Ambiguity requires clarification.
- LLM receives evidence/simulation packets; it does not become the source of truth.
- UI actions are allowlisted and process/edge IDs are validated.
- No arbitrary JavaScript/selector execution from LLM output.

## Security
- API keys/service-role keys remain server-side environment variables.
- No `.env` or secrets in release package.
- No runtime filesystem write/delete primitive may target Atlas content.
