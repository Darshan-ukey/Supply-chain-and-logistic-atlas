# Atlas V6.2.3 + Intelligence v0.6.5 — Pre-build Audit

## Requested release contract
- Frozen Page 0 V6.2.2: immutable.
- Frozen integrated V6.2.2 + Road LTL V1.2: immutable.
- V6.2.3: additive methodology/taxonomy/how-to-read layer only.
- Atlas Intelligence v0.6.5: receives the same governed methodology/definitions as the UI.
- No automatic correction of frozen Atlas content.

## Baseline findings from v0.6.4
PASS — full Page 0 + LTL integrated source present.
PASS — LTL structured model, trace, scenario/client twin, evidence intake, research boundary, LLM gateway, Supabase hooks and Human Review retained.
PASS — v0.6.4 semantic resolver handles canonical POD/invoice/claim/BOL/rate traces and current UI context.

### Blockers found
1. Methodology existed implicitly in Page 0/LTL/source records but was not a single governed knowledge asset available to both user and chatbot.
2. No dedicated Page-0 “How to Read the Atlas” walkthrough/taxonomy guide existed.
3. `OTHER` and other repeated surface terms could still be misclassified if exact namespace/current UI context was absent.
4. The LLM prompt required grounding but did not explicitly require user-first plain-English operational explanation followed by provenance/source detail.
5. Process canonical records did not expose provenance/sourceMap strongly enough in the explainer layer.
6. The integrity check assumed deployed `atlas.html` must be byte-identical to V6.2.2; an additive V6.2.3 guide therefore needed a stronger “strip additions -> exact V6.2.2” verification contract.

All six are release blockers for V6.2.3/v0.6.5.
